# G4Composer manuscript reproduction

Minimal pipeline that reproduces the quantitative results in

> Popenda, Dziel, Sarzynska, Szachniuk, Zok.
> *G4Composer: topology-guided 3D structure modeling of canonical and
> non-canonical G-quadruplexes.*

The pipeline builds every model with **engine 16** (`quadro16.awk`) from the
`quadro:latest` Docker image, scores it against the experimental structure with
the **all-heavy-atom** RMSD over the **author chain** named by the input record,
clusters the inputs with Affinity Propagation, and prints every number reported
in the manuscript.

The engine, CYANA and Xplor-NIH are **not** part of this repository. They are
supplied by the `quadro:latest` image, which embeds licensed software and must
not be redistributed.

## Requirements

- Docker with the image `quadro:latest` (engine 16). Build it from the
  `mkdewe/quadro` repository with `tools/build.sh`.
- Python 3.11+ with the packages in `requirements.txt`.
- PyMOL on `PATH` (`pymol -cq`), version 3.1 or newer.
- Network access to `files.rcsb.org` for the reference structures.
- ~1 GB of disk for references and models.

```bash
python3 -m venv .venv
. .venv/bin/activate
pip install -r requirements.txt
```

`run_all.sh` and `run_table1.sh` use `.venv/bin/python` when it exists and fall
back to `python3`.

## Quick start

```bash
# main 546-instance dataset, 12 models per input
JOBS=12 bash pipeline/run_all.sh

# Table 1 default-parameter branch (15 targets)
JOBS=12 bash pipeline/run_table1.sh
```

`run_all.sh` downloads the references, scores the bundled Qplex models, builds
6,516 models, scores them, clusters the inputs, and writes the manuscript
numbers. `run_table1.sh` fetches the 15 Table 1 references, scores the Qplex
models, and builds the nominal-geometry variant used in the third column of
Table 1.

## Protocol

**Engine.** One image, `quadro:latest` (engine 16). The image must include the
`sugar` keyword fix: the original engine-16 parser accepted only the misspelt
`shugar`, so inputs carrying the documented `sugar` field silently used the
default pucker. Each input is built at six CYANA iteration depths (30, 50, 70,
100, 150, 300) in the standard and alternative modes, giving 12 models per
input. Engine 16 is single-pass, so the alternative mode is generated by the
pipeline: `orient`, `rise` and `twist` signs are inverted and positions 2 and 4
are exchanged in every `path` token.

**RMSD.** Hydrogens are removed from both the model and the reference. The
reference is restricted to the author chain named by the input record
(`auth_asym_id`, which PyMOL uses as its chain identifier), not to whichever
chain PyMOL would prefer. The two phosphate-oxygen aliases `OP1`/`O1P` and
`OP2`/`O2P` are normalised. PyMOL `align` is run for one pass (`cycles=0`) and
the RMSD over the common heavy atoms is recorded. This is the value called
"all-heavy-atom RMSD" in the manuscript.

**3D-NuS-Qplex.** The fifteen Qplex models in `qplex/` are rescored with the
same procedure, not taken from published values. They have no chain ID and use
`ADE`/`GUA`/`THY`/`CYT` residue names, so PyMOL aligns them to the reference by
sequence. The files retain the server's hydrogens; both sides are stripped
before alignment, which is why the Table 1 Qplex column differs from the
all-atom values reported previously.

**Energy.** `<name>_energy.txt` is the Xplor-NIH force-field evaluation of the
final coordinates; it is used only to rank models of the same input.

## Inputs and references

- `inputs/current_548/` — the 548 retained input records (546 measured
  instances plus the two synthetic constructs 7ZJ4/7ZJ5, which are kept for the
  clustering but not modelled). `inputs/manifest.csv` pins every file by SHA256.
- `inputs/excluded_inputs.txt` — the 23 records removed from the 571 candidates.
- `references/manifest.csv` — per key, the RCSB URL and the SHA256 of the
  decompressed mmCIF. `fetch_references.py` refuses a file whose hash differs,
  so an upstream change in the PDB archive cannot silently change the numbers.
- `qplex/` — the fifteen 3D-NuS-Qplex models for Table 1, one per target, with
  SHA256 hashes in `qplex/manifest.csv` and provenance in
  `qplex/PROVENANCE.md`. These are scored locally; no published Qplex values are
  reused.

The three mixed DNA/RNA records `4ni7-assembly1-B`, `4ni9-assembly1-B` and
`4ni9-assembly1-D` cannot be built by engine 16 (`ERROR 106 bledna para`).
They are skipped and listed in `work/reports/known_unbuildable.txt`. Two of
them are Affinity Propagation representatives, so the RMSD statistics cover
323 of the 325 representatives.

## Outputs

| path | content |
|---|---|
| `work/data/scores.csv` | per-model heavy-atom RMSD and atom count |
| `work/data/G16_rmsd.txt` | 12-column RMSD table (heavy atoms) |
| `work/data/G16_energy_popr.txt` | 12-column energy table |
| `work/data/table1_*.txt` | default-parameter branch |
| `work/data/qplex_scores.csv` | all-heavy-atom RMSD of the fifteen Qplex models |
| `work/results/AP_unweighted_548/` | Affinity Propagation clusters and representatives |
| `work/reports/numbers.json` | every manuscript statistic |
| `work/reports/S1_table.csv` | subgroup table (S1) |
| `work/reports/table1.csv` | Table 1, including the Qplex column |

## Layout

```
inputs/      548 input records and their manifest
references/  pinned RCSB manifest (files are downloaded into work/)
qplex/       fifteen 3D-NuS-Qplex models and their manifest
pipeline/    the scripts
work/        generated data (git-ignored)
```

## Notes

- The 3D-NuS-Qplex models are bundled and rescored by `score_qplex.py`; the
  Table 1 Qplex column is therefore regenerated from the same protocol as the
  G4Composer columns, not copied from a publication.
- Reference structures are downloaded from RCSB; the manifest is the pinned
  snapshot used for the manuscript.
- The manuscript's RMSD/energy violin (`figures/AP_violin.pdf`) is written to
  `work/results/AP_violin.pdf` by `plot_violin.py`.
